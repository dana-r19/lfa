## Theory

Parsing, or syntactic analysis, serves as the structural validation phase within a compiler infrastructure. It accepts a linear stream of tokens generated by the lexical analyzer and checks them against the operational rules of a specified context-free formal grammar. While the lexical pass isolates strings into distinct categories (such as literals, operators, or keywords), the parser evaluates how these individual units relate to each other grammatically.

A highly critical artifact resulting from this phase is the Abstract Syntax Tree (AST). Unlike a standard concrete parse tree—which explicitly maps out every minor component of the grammar structure including trivial tokens like semicolons or groupings—an AST distills the structural code down to its pure semantic essence. It maps operational rules as internal junction nodes and values or variables as operational child leaf nodes. This nested tree format serves as the foundational data graph for subsequent code optimization, interpretation, and machine compilation phases.

### 1. Lexical Preprocessing Module (`lexer.py`)

This module defines the atomic categories of our language via the TokenType enumeration. The processing loop uses Regular Expressions bound with anchor tags (`^`) to step sequentially through the source text string, filtering out empty whitespaces and creating structured Token objects.
 ```python
# Segment from lexer.py: Utilizing regular expressions to match tokens
TOKEN_REGEX = [
    (TokenType.KEYWORD, r'^(if|else|while|return|int|float)\b'),
    (TokenType.IDENTIFIER, r'^[a-zA-Z_][a-zA-Z0-9_]*'),
    (TokenType.NUMBER, r'^\d+(\.\d+)?'),
    (TokenType.OPERATOR, r'^[+\-**/]'),
]
```
### 2. AST Nodes and Parsing Engine (`parser_ast.py`)

This module houses the custom data model mapping different node behaviors (`AssignNode`, `BinOpNode`, `NumberNode`, `VariableNode`), each providing an indentation print method. The Parser steps through the tokens using structural precedence methods where `parse_expression` handles lower-priority operations (`+`, `-`) and steps down into `parse_term` for higher-priority operators (`*`, `/`).
```python
# Segment from parser_ast.py: Handling binary operations and keeping math precedence
def parse_expression(self) -> ASTNode:
    left = self.parse_term()
    while self.peek() and self.peek().type == TokenType.OPERATOR and self.peek().value in ('+', '-'):
        op_token = self.consume(TokenType.OPERATOR)
        right = self.parse_term()
        left = BinOpNode(left, op_token.value, right)
    return left
```
### 3. Execution Infrastructure Entry (`main.py`)

This serves as the central control runtime pipeline script. It feeds a raw programming string expression directly into the lexer instance, transfers the resulting array objects into the parsing instance, and triggers the terminal graph printing utility.
```python
# Segment from main.py: Running the full parsing pipeline
def main():
    source_code = "result = 5 + 3 * 12 - 2;"
    tokens = Lexer(source_code).tokenize()
    ast_root = Parser(tokens).parse()
    ast_root.print_tree()
```
## Conclusions / Results

This laboratory work successfully demonstrated the process of converting unstructured code strings into structural abstract syntax structures. Using anchored regular expressions kept the initial lexing process lightweight and easy to maintain.

Additionally, leveraging a recursive descent parsing approach naturally handled language precedence. Lower-priority mathematical components gracefully embedded the operations of higher-priority calculation clusters deeper into the node structure, accurately preserving math evaluation rules without requiring auxiliary look-up arrays.
